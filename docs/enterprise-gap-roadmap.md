# Job-Agent 企业级对标任务清单（Enterprise Gap Roadmap）

> 配套：`docs/interview-playbook.md`（简历/面试叙事）。本文用途：把当前 Agent 与企业级实践的差距，排成可逐项执行的任务清单。
> 原则（沿用历史路线图）：渐进式演进，不推翻重做；不堆业务按钮；每项带测试与验收；**面试叙事优先做"有故事可讲"的，不是"技术最牛的"**。
> 排序逻辑：**面试收益 ÷ 实现成本**，环境受限项单独列。

---

## P0：性价比最高（面试高频 + 改动可控）

### G1. 模型分级路由（成本路由）★最优先
- **企业级对照**：企业按任务难度路由模型档位（分类/抽取走小模型，规划/总结走大模型），成本差一个量级。
- **现状**：网关已按 sceneCode 路由到具体模型，但档位选择靠人工配，没有"按难度自动分级"。
- **方案**：意图识别结果带难度标记（规则意图固定档 / LLM 兜底意图按 confidence 分档）；路由解析时按档位选模型组；新增 `LIGHT/STANDARD/PRO` 三档配置（可在 `ai_model_route` 加字段或约定 modelCode 前缀，不改表优先）。
- **验收**：单测覆盖档位选择与降级；Eval 跑一轮对比"全大模型 vs 分级"的成本与通过率变化（只记录，不承诺目标值）。
- **简历故事**："模型成本优化：规则优先 + 意图分级路由，闲聊/分类场景走轻量模型，在通过率不降的前提下降低成本（待补数字）"。

### G2. Replan / 反思循环

> 状态：✅ 已完成（2026-10-17，全量 185 单测全绿）。部署需配 `PLAN_REPLAN` 场景（ai_model_route），未配则自动退化为原失败语义。
- **企业级对照**：Plan-and-Execute 的"P"要有动态性——执行结果不满足完成条件时重新规划（ReAct/Reflection 思想）。
- **现状**：模板主干 + LLM 补步是一次性规划，执行失败只能整计划失败。
- **方案**：`finishRun` 前校验完成条件；不达标且 replan 次数 < 上限（如 2）时，带"已完成步骤摘要 + 失败原因"回网关重新生成追加步骤（仍受 Tool Schema 白名单约束）；次数用尽走现有失败路径。
- **验收**：单测：模拟执行不达标 → 触发 replan → 上限后终止；Trace/Observation 有 replan 事件。
- **简历故事**："从一次性规划到带反思的规划：完成条件校验 + 有界 replan，Agent 能处理'第一步发现假设不成立'的场景"。

### G3. Eval 增强：LLM-as-judge + 自动化门禁

> 状态：✅ 已完成（2026-10-17，全量 188 单测全绿）。① LLM judge 四维评分（accuracy/completeness/groundedness/format）+ JSON 约束 + 失败降级规则分，3 个单测覆盖；② `scripts/eval-quality-gate.sh` 质量门禁（自动登录→触发回归→轮询→双闸门判定），文档见 `docs/eval-quality-gate.md`。
- **企业级对照**：评估不能只有规则匹配——语义类输出（回答质量）要 LLM 评判；CI 每日跑防退化。
- **现状**：严格匹配 + 手动异步回归 + 基线字段已具备。
- **方案**：① 新增 `EVAL_JUDGE` 网关场景，对回答质量类用例做 1-5 分评判（prompt 带评分标准 + 输出 JSON 约束 + 失败降级到规则分）；② 质量门禁脚本：VM/自建 runner 每日跑核心数据集，passRate 相对基线下降超阈值即非零退出（GitHub Actions 连不上开发库，用自建 runner 或本地脚本，见"环境受限项"）。
- **验收**：judge 单测（mock 网关）；门禁脚本跑通一轮并产出基线报告。
- **简历故事**："Eval 从'能跑'到'能防退化'：规则匹配 + LLM 评判双轨，基线比对 + 定时门禁，Prompt 变更不再裸奔"。

## P1：工程深度亮点（面试区分度）

### G4. 工具并行执行

> 状态：✅ 已完成（2026-10-17，全量 191 单测全绿）。零 DB 改动：依赖直接复用 `{{step_N.output.xxx}}` 占位符静态分析；安全规则=只读并行/写串行屏障。
- **企业级对照**：无依赖步骤并发是有栈工程师的基本操作（线程池 + DAG）。
- **现状**：Executor 串行按步骤号执行（已有占位符传参表达依赖）。
- **方案**：规划时给步骤标 `dependsOn`（模板静态标 + LLM 补步时声明）；执行器按依赖分层，同层用有界线程池并发；**注意 AgentRuntimeContext 的 ThreadLocal 传递（TransmittableThreadLocal 或显式透传）**；单步失败不影响同层其他步骤，汇总后按需 replan。
- **验收**：单测：三层依赖图只并发同层、计数验证工具交互次数；耗时对比（mock 延迟）。
- **简历故事**："执行器从串行到依赖分层并发：DAG 分层 + 有界线程池 + 上下文传递，无依赖步骤总耗时从累加变取 max"。

### G5. 流式输出（SSE）

> 状态：✅ 已完成（2026-10-17，全量 202 单测全绿）。v1 范围：主链路不变，仅总结生成流式；流式失败自动降级阻塞。零新依赖（HttpURLConnection 手写 SSE）。
- **企业级对照**：对话产品标配；考察异步/响应式能力。
- **现状**：总结结果是整段返回。
- **方案**：`SseEmitter` + 网关流式回调（RestTemplate 不支持流式，用 `WebClient` 或 OkHttp 的流式读，或供应商 stream 接口）；前端 EventSource 逐字渲染；中断处理（客户端断开取消上游）；失败时已输出部分 + 降级提示。
- **验收**：单测覆盖流式解析与中断；前端可演示逐字输出。
- **简历故事**："总结场景流式改造：SSE + 流式 HTTP 解析 + 断线取消，首字节延迟从整段生成时间降到（待补数字）"。

### G6. MCP 真连接（一个就够）

> 状态：✅ 已完成（2026-10-18，Bootstrap 209 + Mcp-Tools 11 单测全绿）。自建 MCP Server（`POST /mcp`，JSON-RPC 2.0：initialize/tools/list/tools/call/ping）+ 零依赖手写客户端 + Agent 主链路接入（首个激活：招聘平台搜索）+ 后台真实协议帧展示。连接器业务真实化（真连邮箱/平台）需外部授权配置，与协议激活解耦，列为后续项。
- **企业级对照**：MCP 是工具接入事实标准；会协议是明确加分项。
- **现状**：连接器是预览桩（README 已正名）。
- **方案**：引入 `langchain4j-mcp` 或手写 JSON-RPC 客户端，激活**一个**真实 server（filesystem 或邮件 IMAP），把对应连接器从 PREVIEW 改为真实调用；保留 Guardrails 确认链。
- **验收**：真实调用演示 + 单测（mock JSON-RPC）。
- **简历故事**："工具层从预览桩到 MCP 协议接入：tools/list + tools/call，一个真实 server 跑通，安全确认链不变"。

## P2：深度项（面试极亮点，按兴趣选）

### G7. 记忆写入门控 + 分层

> 状态：✅ 已完成（2026-10-18，Bootstrap 221 单测全绿）。AgentMemoryConflictGate 三条确定性规则（等价值跳过/临时表达拦截/异 key 值重叠留审）+ MEMORY 观测事件 + 查询失败降级放行。
- 不是所有对话都值得记：写入前判"稳定性/重要性"（如偏好类才记，一次性任务参数不记）；长期记忆分层（画像/事实/事件）。
- 简历故事："记忆从'全量沉淀'到'门控写入'：写入前评估信息密度，记忆库增长速率和 Prompt 噪声双降"。

### G8. 查询改写（REWRITE 场景）

> 状态：✅ 已完成（2026-10-18，Bootstrap 231 单测全绿）。AgentQueryRewriter：信号词门控（自包含消息不花模型钱）+ LIGHT 档改写 + 输出清洗（引号/前缀循环剥离）+ 失败回退原消息；接入 Planner/RAG/记忆检索。部署需在后台配 `QUERY_REWRITE` 场景，未配自动退化为原消息。
- 总结/RAG 前用 LLM 把口语问题改写成检索式（走已有网关，默认关闭，配置开关）。
- 验收：Eval ragHitRate 前后对比（只记录基线）。
- 简历故事："RAG 前置查询改写：口语→检索式，ragHitRate 从 X 到 Y（待补数字）"。

### G9. 补偿事务（Saga 思想）

> 状态：✅ 已完成（2026-10-18，Bootstrap 245 单测全绿）。方案①：补偿注册表（Spring 收集 action bean）+ 终失败逆序补偿 + 三类补偿语义（可补偿/不可逆/档案保留）+ COMPENSATION 观测事件。零 DB 改动；升级路径=补偿日志表（方案②）。
- 副作用工具定义"撤销"语义（如 GreetingGenerateTool 生成删除接口）， replan/失败时按已执行步骤逆序补偿。
- 简历故事："从'重试幂等'到'失败可补偿'：为副作用工具设计撤销动作，执行链路具备 Saga 式回滚能力"。

### G10. 语义缓存
- query embedding 相似度超阈值直接返回历史答案（带 TTL）；成本/延迟双降，但要处理"缓存了过期答案"问题。
- 简历故事："语义缓存：相似问题命中即返回，缓存命中率 X%，P50 延迟降 Y（待补数字）"。

## 执行建议

1. **节奏**：P0 三项（G1→G2→G3）是"成本/智能/质量"三个面试高频叙事，优先；G4/G5 是工程深度，二选一或都做。
2. **每项纪律**（和历史任务一样）：先出方案确认 → 实现 → 单测 → 提交信息写"改了什么/为什么" → 更新 `interview-playbook.md` 的数字清单和简历 bullet。
3. **叙事复利**：每完成一项，简历就多一条"审计→发现→升级"的实证，面试故事线越来越难被当成 Demo。
