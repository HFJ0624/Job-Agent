## 1. 一句话定位（开场 30 秒）

> "一个围绕求职场景的 Plan-and-Execute Agent。我从一个能跑通的模板化 Demo 开始，做了一次代码级审计，发现执行可靠性、上下文管理、质量度量上的缺口，然后逐项补齐：步骤级幂等与崩溃恢复、模型网关退避/HALF_OPEN/限流、多轮上下文与滚动摘要、记忆 TTL 与冲突裁决、Eval 异步回归。现在 221 个单测全绿，`mvn test` 可当场演示。"

关键词：**审计驱动**（不是堆功能）、**每项带测试**（不是裸奔）、**有数字**。

## 2. 简历 Bullet 库（按模块，直接取用）

> 用法：每个模块选 1-2 条，量化处用你的真实数字替换「待补」。

### Agent 执行内核
- 设计 Plan-and-Execute 执行器：步骤级状态机 + 幂等键（`planId:stepNo:toolName:参数hash`），崩溃重试时已完成步骤零重复调用，副作用工具（写沟通记录/评分）不重复落库；FAILED 计划支持从首个未完成步骤续跑（retry_count 上限保护）。
- 并行执行（G4）：只读步骤按依赖分层并行（依赖=占位符引用静态分析，零 DB 改动），写副作用步骤是串行屏障（绝不并发写业务数据）；有界线程池 + CallerRuns 兜底；并行时快照传递 ThreadLocal 运行时上下文。
- SSE 流式输出（G5）：`SseEmitter` + `HttpURLConnection` 手写 SSE 流式调用（零新依赖），总结 token 实时推送；流式失败自动降级阻塞（增强而非故障点）；前端 fetch ReadableStream 逐字渲染 + 回退。
- MCP 真连接（G6）：自建 MCP Server（`POST /mcp`，JSON-RPC 2.0 协议子集 initialize/tools/list/tools/call）+ 手写零依赖客户端（保留原始协议帧、错误码映射）+ 接入 Agent 工具调用链（首个激活：招聘平台搜索，走 Guardrails）；后台展示真实 JSON-RPC 帧。诚实边界：连接器业务真实化（真连邮箱/平台）需外部授权，与协议激活解耦。
- 记忆门控（G7）：写入前冲突预检（等价值跳过/临时表达拦截/同类型异 key 值重叠留审），与既有“同 key 覆盖置信度裁决”分层协作；门控查询故障降级放行——防护组件自身不能成为故障点。
- 执行可观测：幂等命中以独立事件上报，后台可统计"真实执行 vs 命中"比例（待补：首轮命中率）。

### 规划层
- 意图识别“规则优先 + LLM 兜底”（规则命中不调模型，省成本）；规划“模板主干 + LLM 补步”，LLM 只能从 Tool Schema 白名单选工具——模型参与规划但不突破确定性安全边界。
- Replan 反思循环：步骤失败时基于「用户目标 + 已完成步骤摘要 + 失败原因」让 LLM 给出替代步骤（白名单校验 + 有界次数 + 失败降级），失败路径放弃、替代步骤追加续跑——Agent 从“一次规划”变为“执行中可改道”。

### Guardrails（安全五层）
- 输入 Prompt 注入检测、PII 脱敏（手机/邮箱/IP/身份证）、工具白名单 + 越权拦截、敏感操作服务端强制确认（行动确认中心 HITL）、幻觉检测（执行失败但声称成功 → 自动替换话术）。

### 模型网关（自研，拒绝说"调 API"）
- 模型路由（主备 / 灰度 / AB 分流）+ Prompt 版本化运行时（后台改线上行为，无需发版）。
- 稳定性：指数退避重试（仅 429/5xx/超时，4xx 不重试）、HALF_OPEN 熔断（冷却后放行单个探测请求，条件更新防并发探测）、场景 + 用户双维限流（手写令牌桶，零依赖）。
- 成本统计 SQL 聚合（COUNT/SUM/AVG 单行返回，替代全表拉内存）。

### 上下文工程
- Context Builder：最近 N 轮历史 + 字符预算分配（历史 30%/记忆 20%/执行 40%）+ 超预算滚动摘要（CONTEXT_SUMMARY 增量压缩缓存）；历史入提示词前强制脱敏。

### Memory 治理
- TTL 过期归档（每日调度）；冲突按来源置信度裁决（后台人工 > 用户明述 > LLM 抽取 > 工具结果），低置信度不覆盖高置信度、标记待确认；修复"读引发写放大"（召回只更新 last_used_time 单列，排序键改用 create_time）。

### RAG
- 混合检索（语义 ×0.65 + 关键词 ×0.35）+ 规则重排 + 失败降级（RAG 挂了聊天不中断，Trace 标记 FAILED）+ 引用 + 防注入声明。

### Eval（质量闭环）
- 严格匹配（下划线/大小写/全半角/空白变体不误过，替换原 contains）；批量回归异步化（Workflow 队列执行、前端轮询、批次幂等）；LLM-as-judge 四维评分（准确/完整/有据/格式，模型不可用自动降级规则分）；基线比对与失败诊断；质量门禁脚本（passRate 双闸门，防退化）。

## 3. 演进故事线（v1 → v3，按模块）

> 面试讲法："我刚开始……，后来审计发现……，于是……"。**讲你修过的问题，比讲有的功能可信十倍。**

| 模块 | v1（刚开始） | 发现的问题 | v2/v3（后续升级） |
|---|---|---|---|
| 执行 | 模板化顺序执行，只有计划级幂等 | 中途崩溃重试会**重复调用已成功步骤**（重复写业务数据）；FAILED 计划被幂等逻辑永久挡回 | 步骤级幂等键 + 状态抢占 + 崩溃恢复 + RUNNING 超时回收 + 步骤间占位符传参 → Replan 失败改道（G2）→ 只读步骤并行执行（G4） |
| 规划 | 纯关键词意图、8 个硬编码模板、正则抽参 | 词表外表达全部落空，面试称"自主规划"会穿帮 | 规则 + LLM 兜底意图/参数抽取 → LLM 白名单补步 |
| 网关 | 主备切换、立即重试、两态熔断 | 立即重试打爆下游；冷却后直接放行没有探测 | 指数退避 + 错误分类（4xx 不重试）→ HALF_OPEN 单探测 → 双维限流 → 成本 SQL 化 |
| 上下文 | 总结提示词只有当前轮 | 多轮对话语义丢失；无预算概念 | 多轮历史窗口 + 预算分配 → 滚动摘要压缩 |
| 记忆 | 词重叠召回；每次召回都 updateById | 读引发写放大（召回即改库还顶乱排序）；新旧偏好静默覆盖 | TTL + 冲突置信度裁决 + 单列更新 + 排序键改造 |
| RAG | 基础设施齐全但**没接进主链路**（死代码） | "你的 RAG 在哪被调用"一问就穿 | 接线 + 意图门控 + 混合检索 + 降级 + rerank |
| 质量 | 手工触发、同步跑、contains 匹配 | 大数据集 HTTP 超时；下划线/大小写变体误过；"改坏了不知道" | 异步化 + 严格匹配 + LLM-as-judge + 基线比对 + 质量门禁脚本（G3） |
| 测试 | `mvn test` 编译失败、43 个散测 | "测试全过"是假的 | 基座修复 + 主链路单测 → 169 全绿（集成测试见 gap-roadmap） |

## 4. 面试八问 · 标准答案要点

**Q1：你的 Agent 和直接调 OpenAI 有什么区别？**
> 分层：意图/规划（Planner）→ 执行（Executor，幂等+恢复）→ 护栏（五层）→ 记忆（画像+召回+治理）→ 评测（Eval）。裸调 API 只有"问-答"；我要回答的是"失败了怎么办、改了怎么知道、贵了怎么控、输出不安全怎么办"。

**Q2：工具执行超时了怎么办？重试会不会重复执行？**
> 三个机制：① 步骤幂等键（planId+stepNo+tool+参数hash），执行前查同计划近期成功记录，命中复用；② 执行前条件更新抢占（`UPDATE ... WHERE status IN (PENDING,FAILED)`，影响行 0 说明被抢先）；③ RUNNING 残留按超时（10 分钟）标记恢复。Trace 里区分 `[IDEMPOTENT_HIT]`，可统计真实执行比例。

**Q3：模型挂了/被限流怎么办？**
> 网关侧：指数退避（仅 429/5xx/超时重试，4xx 不重试）、失败累计触发熔断；HALF_OPEN 冷却后只放一个探测请求（条件更新防并发探测），成功关闭、失败重开。调用方侧：网关失败降级到确定性兜底（如规则摘要），聊天不中断。

**Q4：上下文一直增长怎么办？**
> Context Builder：最近 N 轮窗口 + 单条截断 + 总预算（字符近似 token）；超预算的更早历史用 CONTEXT_SUMMARY 场景增量压缩成一段摘要缓存到会话（summary_upto_message_id 记录已压缩位置，避免重复压缩）。

**Q5：怎么证明 Agent 效果好？改 Prompt 怎么知道没改坏？**
> Eval 平台：数据集 + 严格匹配 + 批量回归 + LLM-as-judge + 基线比对（通过率/工具准确率相对基线的变化值）+ 质量门禁脚本（绝对下限 + 相对下降双闸门，见 docs/eval-quality-gate.md）。

**Q6：多轮对话和用户偏好怎么管？**
> 短期：多轮历史窗口 + 滚动摘要；长期：记忆画像（稳定事实压缩）+ 相关记忆召回，带 TTL 过期和冲突置信度裁决（用户明述 > 工具结果，低置信度不覆盖）。

**Q7：输出安全怎么保证？**
> 五层：输入注入检测 → 工具白名单/越权（ToolAccessGuard，LLM 只能选注册表内工具）→ 敏感操作 HITL 确认（行动确认中心）→ PII 脱敏（入提示词和落库两条路径）→ 幻觉检测（执行失败但声称成功自动替换）。对照 OWASP LLM Top 10 覆盖了注入/敏感信息/过度代理部分。

**Q8：模型成本怎么控？**
> 三层：规则优先（命中不调模型）→ 场景级限流（令牌桶防打爆）→ 成本可观测（每次调用落 token/费用，SQL 聚合看板）。下一步：模型分级路由（简单场景小模型）在 gap-roadmap P0。

## 5. 企业级对照（诚实版，面试主动说）

| 维度 | 企业级常见做法 | 本项目现状 |
|---|---|---|
| 编排 | 图编排/状态机、ReAct 混合、Replan 反思循环 | 模板 + LLM 补步；Replan 在计划中 |
| 记忆 | 分层（工作/情景/语义/程序性）、写入门控 | 长期记忆 + 治理；分层/门控在计划中 |
| 工具 | MCP 标准协议、并行调用 | 连接器为预览桩（已正名）；并行在计划中 |
| RAG | 查询改写、多路召回 + RRF、cross-encoder、ragas 评估 | 混合 + 规则重排；改写/评估在计划中 |
| 可靠性 | Saga/补偿事务、checkpoint | HITL 有；补偿事务在计划中 |
| 成本 | 模型分级路由、语义缓存 | 未做（gap-roadmap P0） |
| 工程 | 流式输出 SSE、多模态 | 未做（gap-roadmap P1） |
| 评估 | LLM-as-judge、在线评估、反馈闭环 | 严格匹配 + 基线；judge/CI 在计划中 |

> 讲法："这些差距我列了清单并按优先级排了（enterprise-gap-roadmap），企业级方案我调研过，选什么取决于投入产出——比如补偿事务面试极亮点但业务收益低，我排在后面。"

## 6. 讲"不像 Demo"的三个技巧

1. **永远带数字**：169 单测、退避参数（base 500ms × 2^n 封顶 4s ± 抖动 200ms）、预算比例（30/20/40）、记忆 TTL 默认 180 天。没有数字的"我做了熔断"像 Demo。
2. **讲失败和修复**："审计发现 Executor 缺步骤幂等，重试会重复写沟通记录——我设计了幂等键 + 状态抢占 + 崩溃恢复，单测证明已完成步骤二次调用为 0。"
3. **主动说边界**："限流是进程内令牌桶，多实例部署要换 Redis 分布式；向量索引因 2048 维跳过，选型（降维/halfvec/HNSW）待定。"——知道什么没做、为什么，是工程师思维的直接证据。

## 7. 数字清单（背下来，随时抛）

- 测试：**221 个单测全绿**（Bootstrap；Mcp-Tools 模块另有 11 个），`mvn -pl Job-Agent-Bootstrap -am test` 可演示

- Eval：工具/参数/关键词/RAG 四类指标 + 基线 delta
- 待补数字：Eval 首轮通过率基线、幂等命中率、成本对比（分级路由后）
